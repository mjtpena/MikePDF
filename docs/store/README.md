# Publishing MikePDF to the Microsoft Store

This is the runbook. Everything an agent can do is done or scripted; the steps marked **You** need your Microsoft account and can't be delegated.

| File | Use |
|---|---|
| [listing.md](listing.md) | Store listing text to paste into Partner Center |
| [certification-notes.md](certification-notes.md) | `runFullTrust` justification, notes for certification testers, age-rating answers |
| [../user/privacy.md](../user/privacy.md) | Privacy policy (its public URL goes in the listing) |
| `build/store/identity.json` | Package identity; replace the placeholders in step 2 |
| `build/store/assets/` | Icon and tile artwork, regenerated by `build/store/generate-assets.py` |
| `.github/workflows/store-release.yml` | Builds the `.msixupload` in CI |

## Before you submit: what this release is
The first package is a **preview reader**. It isn't the v1.0 described in the master prompt: performance budgets haven't been measured on reference hardware, and annotations, forms, printing and save aren't in it. See [docs/STATUS.md](../STATUS.md).

Start with a **private audience**. Going public can't be undone.

## Steps
### 1. Merge to `main` (You)
Merge the open PR. The privacy policy URL and the licence detection both depend on it.

### 2. Developer account and name (You)
1. Create the account from **https://storedeveloper.microsoft.com**. It's free from there; other entry points show the older paid flow.
2. **Choose the account type carefully.** Individual accounts are for distribution not tied to a business, and they can't convert to Company later. If this will be published under a business, use a Company account: it needs a business email and D-U-N-S or documents, and can take 2–5 business days. Individual verification uses government ID and a selfie.
3. **Reserve the app name.** It's held for 3 months. The project is called MikePDF. Web searches on 2026-11-02 found no app with that name, but they aren't a trademark search and this isn't legal advice, so Partner Center decides whether the name is free. The display name is one setting, so changing it costs nothing now.
4. In Partner Center, open **Product management > Product identity** and copy these into `build/store/identity.json` (they're case-sensitive): `Package/Identity/Name`, `Package/Identity/Publisher`, `Package/Properties/PublisherDisplayName`. Also set `DisplayName` to the reserved name, and commit.

### 3. Build the upload
Run **Actions > Store release > Run workflow** with the version (first release `1.0.0.0`). Download the `store-upload` artifact, which has the `.msixupload` with x64 and ARM64 packages. Check the `wack-report` artifact too.

### 4. Create the submission (You)
1. **Pricing:** Free. **Markets:** your choice. **Audience:** Private, with your test group.
2. **Properties:** category Productivity. Add the privacy policy URL: `https://github.com/mjtpena/QuirePDF/blob/main/docs/user/privacy.md`.
3. **Age ratings:** complete the questionnaire with the answers in [certification-notes.md](certification-notes.md).
4. **Packages:** upload the `.msixupload`.
5. **Store listing:** paste from [listing.md](listing.md). Upload the 1:1 tile from `build/store/assets/store-listing/` and the screenshots from `docs/store/screenshots/`.
6. **Submission options:** paste the `runFullTrust` justification and the tester notes from [certification-notes.md](certification-notes.md).
7. Submit. Certification can take a few days, and a restricted capability can add time.

### 5. Test from the Store, then decide
Install from the private listing **as a standard (non-administrator) user**, on a clean machine, and open a PDF. CI has only run the package as an administrator, with a test certificate. Also test:
- **ARM64**, which has only run on CI runners so far.
- **A machine with Smart App Control on.** The engine has no signature of its own, and nothing official confirms that the Store's package signature is enough ([R-43](../risks.md)). If documents won't open there, don't go public.
- **Narrator**, using `spikes/S7/narrator-script.md`, before you tick "accessible" in the listing.
- **Light and high-contrast themes**, which have never been seen running. Add them to the listing if they look right.

Going public is a separate decision.

### 6. Optional: automate updates (You)
The first submission must be manual. After that, CI can publish updates:
1. Create an Entra ID app, and associate it with Partner Center with the Manager role.
2. Add repository secrets `STORE_TENANT_ID`, `STORE_SELLER_ID`, `STORE_CLIENT_ID` and `STORE_CLIENT_SECRET`, plus `STORE_PRODUCT_ID`.
3. Set the repository variable `STORE_PUBLISH_ENABLED` to `true`.

Runs with **publish** ticked then submit via the Microsoft Store Developer CLI.
