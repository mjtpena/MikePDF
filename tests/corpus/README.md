# The MikePDF corpus

`manifest.json` is the source of truth ([ADR-0010](../../docs/adr/0010-corpus-sourcing.md) and its amendment of 2026-11-03). It lists every file with where it comes from, its licence and where that licence was read, SHA-256, size, tags, tiers and what a correct run does with it. **No PDF is committed here.** `mikepdf-render corpus fetch --tier core` downloads or generates the files into `build/out/corpus/files/` and checks every one against its hash; a mismatch fails the fetch, and a render refuses to run on a corpus that does not match.

```powershell
dotnet run --project tools/MikePDF.Render -c Release -- corpus check               # validate the manifest (CI runs this)
dotnet run --project tools/MikePDF.Render -c Release -- corpus fetch --tier core   # download, generate, verify (core includes smoke)
dotnet run --project tools/MikePDF.Render -c Release -- corpus verify --tier core
dotnet run --project tools/MikePDF.Render -c Release --no-build -- --tier core --scale 1,2 --out render-out
```

| Tier | Files | Download | Runs | Where |
|---|---|---|---|---|
| smoke | 96 | 3.1 MB | every pull request, x64 and ARM64 | `render-smoke` in `.github/workflows/ci.yml` |
| core | 1,404 (the 96 smoke files and 1,308 more) | 813 MB | every night, x64 and ARM64 | `.github/workflows/nightly-corpus.yml` |
| full | none yet | | | §12.2 asks for 50,000+; see "Not done" |

Tiers nest: a file is listed once, in the smallest tier it belongs to, and `--tier core` runs the smoke files too. §12.2 names about 5,000 files for the core tier; this one has 1,404 because that is what could be licensed file by file (below). The tool's manifest check refuses a core tier under 300 files or without scanned, tagged, form, large-page-count, CJK, RTL, transparency, annotation, encrypted and broken files.

### Two files that take the engine down on purpose

The gate has to show that the engine's hang and crash recovery works, not only that nothing went wrong. Both files are generated by this repository, are valid PDFs, and are in the smoke tier:

| File | What it does | What the gate sees |
|---|---|---|
| `generated/engine-crash-form-fanout.pdf` (6 KB) | Thirty nested Form XObjects, each invoking the next three times: loading the page builds 3^30 objects | The sandbox job runs out of memory, the engine exits (`MemoryLimit`) and is replaced, in about 5 s |
| `generated/engine-hang-tiling-step.pdf` (0.7 KB) | A tiling pattern with a 0.0001 pt step filled over a 14400 pt page keeps PDFium inside one drawing operation | PDFium checks its deadline only about every 100 operations, so the request goes unanswered, the watchdog kills the engine as hung and the supervisor replaces it |

Their entries say `expect.engineEvent` `crash` or `hang`, so the gate **fails** if a run does not see that event, or does not see the engine replaced after it (`ExpectedEngineEventMissing`, `EngineNotRestored`): a file that stopped doing its job would otherwise pass for ever. They render through the engine only (`render.reference` false) because PDFium outside the sandbox would die or spin the same way. What was not established: whether the pattern file ever finishes. It had run for over 200 s on x64 when it was cut off.

### The rules for files from test suites

A repository licence does not prove that each test file in it was the contributor's to give. For the test-suite sources (PDFium, Chromium, qpdf, the PDF Association's, veraPDF) a file is left out when any of these is true; `curation/Build-CoreEntries.ps1` holds the rules and writes every rejection with its reason:

- it embeds a font program that is not from an open-licence family (Liberation, DejaVu, Source, Noto, Computer Modern and the like); Arial, Times New Roman, Calibri, Myriad, Hiragino and Adobe's built-in fonts are proprietary (99 veraPDF files, 28 PDFium, 10 PDF Association, 5 Chromium and 3 qpdf);
- its producer or creator says a desktop application made it (Word, Acrobat, Skia, LibreOffice, pdfTeX ...), so it may come from someone's real document (28 qpdf files, 2 PDFium files);
- it carries a JPEG or JPEG 2000 image over 150 KB, which may be a photograph (5 files); and qpdf, which gave 541 files that passed, is sampled evenly down to 330 (211 not taken);
- it is an expected output of a qpdf test (62), or has the same bytes as a file already in the corpus (7);
- for PDFium files without a hand-written template: it names an author.

These rules read raw bytes. A font in a compressed object stream cannot be seen, so a file whose producer field is empty and whose fonts are hidden passes; the rule narrows the risk, it does not remove it. The real-world sources (Commons, arXiv, Government) do not get the font rule: their licence is the author's or the state's for the document as published, embedded subsets included, as for every published PDF.

### Left out, and why

The manifest's `excluded` list has each with the reason and what was checked: pdf.js `test/pdfs` (1,077 files, no licence or provenance file), py-pdf/sample-files and the PDF Association's pdf20examples (CC BY-SA, not on the allowed list), pdfminer.six samples ("distributed freely" but no licence), pdfcpu (third-party inputs, no provenance), Ghostscript (AGPL), the veraPDF Isartor, TWG and Undefined folders, the Library of Congress (a bot challenge blocks automated fetches; not worked around), the ATO forms, GovDocs1, SafeDocs and Common Crawl, third-party crash files, arXiv papers under the default licence, Commons files that are over 6 MB or CC BY-SA or restricted, and 6 PDFium files from the smoke audit.

## Licences and attribution

Allowed: BSD-3-Clause, Apache-2.0, MIT, CC0-1.0, public domain, CC BY 2.0 to 4.0 (ADR-0003 for the first five; the 2026-11-03 amendment of ADR-0010 for CC BY). The manifest check fails on `UNVERIFIED`, on any other licence, and on a file outside smoke without `licenceEvidence`. [ATTRIBUTION.md](ATTRIBUTION.md) gives the credit CC BY asks for; nothing is redistributed, the files are fetched from their authors' own addresses.

### The per-file audit of PDFium's `testing/resources` (2026-11-03)

Each of the 89 files first in the smoke tier was checked, and the result is in its manifest entry (`audit`):

1. **History.** `git log --follow` on the pinned commit (a blobless clone of `chromium/8125`) gives the commit that added each file, its author and date. Every file came in through a Gerrit change by a PDFium or Chromium contributor, which requires Google's contributor agreement; none was added in bulk from an outside source. 59 have a hand-written template (`.in`) beside them.
2. **Content scan.** Every file was searched for `/Producer`, `/Creator`, `/Author`, `/Title`, XMP packets, `copyright`, `licence`, `all rights reserved`, embedded font programs and image streams.
3. **Look.** Every file with an image, an XMP packet, a font program or a producer string was rendered and looked at.

Result: **83 audited and kept, 6 left out** (each with its reason in `excluded`): `bug_650.pdf` (a page of a third-party AutoCAD tutorial), `embedded_images.pdf` and `annotation_stamp_with_ap.pdf` (Adobe's promotional text "Adobe Acrobat PDF Files" and crops of it), `page_labels.pdf` (the Chrome logo, a trademark), `annotation_ink_multiple.pdf` (embeds an Arial subset) and `annotation_highlight_square_with_ap.pdf` (saved from Word, embeds a Calibri subset). Of the kept files, `text_font.pdf` embeds Liberation Serif (SIL OFL 1.1) and `latin_extended.pdf` embeds Roboto (Apache-2.0); the images in the JPX, JBIG2, DCT and CCITT files are flat colours, gradients or a few words of text made for the test.

What this audit cannot show: that a contributor really held the rights to what they committed. It rests on the contributor agreement and on the content being synthetic. A file that later turns out to have been taken from somewhere should go to the exclusion list with a dated reason. The judgement that a proprietary font subset makes a file doubtful is a conservative one; Opus may want to relax it.

## What the entries expect

`expect` records what the first run showed, reviewed by the author, not yet by a second person. They are regression expectations, not claims about what a file should do in every viewer.

- `Ok` for most. `PasswordRequired` for encrypted files whose passwords the corpus does not know (28). `Damaged` for files broken on purpose (32: truncated, garbage, parser tests). A document that opens but has pages that cannot be loaded says `allowsDamagedPages`.
- **The open rate (§0.3, M2).** Files broken on purpose are not files that should open and do not count. A real-world file that should open and does not is marked `expect.knownIssue` and does count. None of the 399 real-world files (Commons, Government, arXiv) was in that case on the first run.
- Long documents render a sample of pages (`render.pages`, for example the first three, the middle and the last of a 2,124-page bill).

## Adding a file

1. Put it in a scratch folder, **never** in the repository. Work out its `sha256` (`Get-FileHash -Algorithm SHA256`) and size.
2. Add an entry to `manifest.json` (copy a neighbour): `id`, `source`, `licence`, `licenceEvidence`, `redistributable`, `sha256`, `bytes`, `tags`, `tiers`, `expect`. A fetch address must name a version that does not change (a commit, not a branch).
3. For a generated file, add the generator to `CorpusGenerators.All`, run `mikepdf-render corpus generate <folder>`, and use the hash it prints.
4. `corpus check`, `corpus fetch`, then render the tier, review the report, and refresh `baselines/<tier>-<arch>.json` with `--write-baseline`. The ARM64 baseline comes from the CI run's artifact `baseline-candidate.json`.

[curation/](curation/) has the scripts that built the core tier's entries (listing candidates, downloading, scanning, applying the rules, writing observed expectations). They are how the work was done, not part of any gate.

## Baselines

`baselines/<tier>-<arch>.json` holds each page's SSIM and the open rate at the last accepted run (see [tools/MikePDF.Render/README.md](../../tools/MikePDF.Render/README.md)). A run fails on a page below its baseline by more than 0.002 and on an open rate below the baseline's. A missing baseline for an architecture means only the absolute 0.98 bar applies.

## Not done

- **The core tier is 1,404 files, not about 5,000, and there is no full tier.** More needs sources with a licence that can be read per file; Wikimedia Commons and arXiv could give thousands more at the cost of download time.
- **Page sampling.** Documents over 40 pages render 5 pages, not all of them.
- **Real-world forms and tagged PDFs are thin.** Most forms and tagged files are test-suite files; the real ones are the IRS forms and a handful of Commons files. Business documents (invoices, contracts, bank statements, slide decks) are not covered: no public source with a clear licence was found. The ATO forms were not done.
- **No Korean or Urdu real-world document.**
- **The per-file font and producer rules cannot see inside compressed objects.**
