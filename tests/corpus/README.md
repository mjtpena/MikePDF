# The MikePDF corpus

`manifest.json` is the source of truth ([ADR-0010](../../docs/adr/0010-corpus-sourcing.md)). It lists every file with where it comes from, its licence, SHA-256, size, tags, tiers and what a correct run does with it. **No PDF is committed here.** `mikepdf-render corpus fetch --tier smoke` downloads or generates the files into `build/out/corpus/files/` and checks every one against its hash; a mismatch fails the fetch, and `mikepdf-render --tier smoke` refuses to run on a corpus that does not match.

```powershell
dotnet run --project tools/MikePDF.Render -c Release -- corpus check               # validate the manifest (CI runs this)
dotnet run --project tools/MikePDF.Render -c Release -- corpus fetch --tier smoke  # download, generate, verify
dotnet run --project tools/MikePDF.Render -c Release -- corpus verify --tier smoke
```

## The smoke tier

100 files, run on every pull request, at 1x and 2x, on x64 and ARM64.

| Source | Files | Licence | Notes |
|---|---|---|---|
| PDFium `testing/resources` at commit `43d55e42` (the head of `chromium/8125`, the branch the pinned engine is built from) | 89 | BSD-3-Clause (ADR-0010: VERIFIED) | Fetched from `pdfium.googlesource.com` as base64 (`?format=TEXT`) and verified by SHA-256 |
| Generated by `Corpus/CorpusGenerators.cs` | 11 | Apache-2.0 (the project's own) | Deterministic, uncompressed, so the hash never moves. Making one differently is a manifest change on purpose |

Coverage (a test, `TheSmokeTierHasAtLeast30FilesCoveringWhatTheGateAsksFor`, keeps it): text (Latin, RTL, vertical, Type 3, standard fonts), vector (shadings, patterns, clipping), images (DCT, JPX, **JBIG2** x5, **CCITT** x1), AcroForms, annotations (ink, stamp, line, polygon, highlight, free text, file attachment), **encrypted** (one with a known password; revisions 2, 3, 5 and 6 opened without theirs, to check the handlers answer `PasswordRequired`), **broken xref** and trailers (rebuilt by PDFium or `Damaged`), a **10,000-page** document (first three, middle and last page rendered), **rotated** pages (`/Rotate` 0 to 270 and inherited), **CropBox offsets** (negative-origin MediaBox, offset and rotated CropBox, CropBox outside the MediaBox, reversed corners), linearised files, a 14400 x 14400 pt page, 6000 nested `q` operators, 36 blended layers.

`expect` records what the first run showed (reviewed by the author, not yet by a second person): `Ok` for most; `Damaged` for the truncated and garbage files and for five PDFium parser-test files; `PasswordRequired` for four encrypted files whose passwords the corpus does not know. These are regression expectations, not claims about what the files "should" do in every viewer.

## Licences

Every entry has a licence from the list ADR-0003 allows, `redistributable: true`, and a source. The manifest check fails on `UNVERIFIED` anywhere. Left out, with the reason, in the manifest's `excluded` list: pdf.js `test/pdfs` (per-file licences unverified), the veraPDF corpus, GovDocs1, SafeDocs and Common Crawl samples, third-party crash files, and PDFium's `xfa` and `javascript` folders (BSD-licensed, but they test features the pinned build does not have: candidates for the core tier). Each needs a licence check before it enters a tier.

Known gap: the BSD-3-Clause licence of PDFium's `testing/resources` is taken from ADR-0010 and the repository's top-level licence. The individual files were not audited for third-party content; the image-heavy ones (for example `embedded_images.pdf`, `annotation_stamp_with_ap.pdf`, the JPX and JBIG2 files) may embed image data whose origin was not traced. Opus should decide whether that is acceptable or whether those files move to the exclusion list.

## Adding a file

1. Put it in a scratch folder, **never** in the repository. Work out its `sha256` (`Get-FileHash -Algorithm SHA256`) and size.
2. Add an entry to `manifest.json` (copy a neighbour): `id`, `source`, `licence`, `redistributable`, `sha256`, `bytes`, `tags`, `tiers`, `expect`. For a file that must render only some pages, add `render.pages`.
3. For a generated file, add the generator to `CorpusGenerators.All`, run `mikepdf-render corpus generate <folder>`, and use the hash it prints.
4. `corpus check`, `corpus fetch`, then render the tier, review the report, and refresh `baselines/smoke-<arch>.json` with `--write-baseline`. The ARM64 baseline comes from the `render-smoke-arm64` CI run (artifact `baseline-candidate.json`).

## Baselines

`baselines/<tier>-<arch>.json` holds each page's SSIM at the last accepted run (see [tools/MikePDF.Render/README.md](../../tools/MikePDF.Render/README.md)). A missing baseline for an architecture means only the absolute 0.98 bar applies.
